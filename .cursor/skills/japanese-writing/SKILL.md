# 日本語の書き方

書く前にこのファイルを読む。Gemini や人間の指摘は、文を直した同じ変更で、ここに一般則を足す。チャットに残して終わらない。既に書いてある指摘を、次の文で繰り返さない。

設計文書の契約用語を、利用者向けの文へそのまま持ち込まない。設計を変えるときは設計 PR が先で、このスキルはコメントの言葉を決める。

## 文の形

- 常体。敬体を混ぜない。翻訳調（「〜することとする」「〜を行う」の連発）にしない
- `。` と `.` は、文末にも文の途中にも置かない。README の地の文だけ `。` を許す
- 補足は（）。並列は、。前の節が進行・状態なら「しており」「ており」でつなぐ
- 「している。もう一方は」は禁止。「しており、もう一方は」
- テストの前提・手順・期待も同じ。メソッド名の「こと」で終えてよい

## 言葉

利用者とコメントの読者が、設計を開かなくても意味が取れる言葉を使う。

| 書かない | 書く |
| --- | --- |
| 哨兵 | ワークフォルダ全体のロック |
| キャンセル、待ちを切る | 取り消し、待ちを取り消す |
| サイドカー | ステージングファイル（`.txnew`） |
| 本物は触らない（残るのがジャーナルのとき） | ジャーナルは残る |
| 優先した全体の結果 | 優先順位で選んだ全体の結果 |
| 成り行き | 扱い |
| 全部（同じファイルが「すべて」のとき） | すべて |
| 作っている（外部が既に書いたとき） | 外部で既に作成されている |
| 足している（外部がファイルを足したとき） | 追加されている |
| か（真偽を聞く述語で、隣が「かどうか」のとき） | かどうか |
| 〜で、（状態を言い切って次へ続けるとき） | 〜であり |
| と競合（動詞が欠けているとき） | と競合する |
| この呼び出しの失敗は呼び出し側へ返す | 呼び出し側が元の例外を返す |
| 予約する（すでに予約が終わっているとき） | 予約した |
| 〜への上げ | 〜に上げる |
| summary と remarks で止めている対象が違う | メソッド名・summary・remarks の主語を揃える |
| 検出条件より広い言い方（「外から変わった」など） | 実際の判定（記録との差） |
| 空として（意味が空文字列のとき） | 空文字列として |
| ストリームを組む | ストリームを介す、用意する、組み立てる |

`docs/design.md` に既にある「哨兵」は、設計の既存語として残っている。XML、README、テストの説明、新しく書くコメントでは使わない。既存コメントを直すときも置き換える。

bool を言葉で書くとき、同じファイルの param が `<see langword="true"/>` なら summary もそれに合わせる。

例外メッセージは、設計の用語に合わせる。あいまいな「中」でフォルダ自身と配下をまとめて書かない。

## レビューのあと

1. 差し替え案を、同種の文が残っていないか探してから反映する
2. その指摘が上の表や「文の形」に無ければ、個別の文ではなく一般則としてここに足す
3. 足してから `./build.ps1` に進む
